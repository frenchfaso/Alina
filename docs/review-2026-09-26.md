# Review: Calendar, workers and hosted research

Reviewed the current code and the changes since the preceding release, with
particular attention to the loop, provider selection, tool authority, file I/O,
job lifecycle, Telegram delivery, account state and compatibility. This is a
release review for the trusted-device POC, not a security certification.

## Findings addressed

- The old catalog client version hid Sol 6. Version 0.156.0 exposes it on the
  configured account. Cache protocol metadata now forces a refresh after an
  upgrade while the account binding preserves personal model/effort preferences.
- Hosted research previously followed the main model and forced low effort.
  It now selects Sol 6 high independently. Main-agent overrides are per call,
  catalog-validated and logged accurately; workers cannot override them.
- A serialized inference gate would make a long worker request block chat.
  One global worker slot and a separate worker gate permit at most one worker
  inference alongside the ordinary chat/dream gate. The loop itself is reused.
- Workers receive explicit task context and input copies, not the main history
  or soul. Tool dispatch excludes Calendar, memory, configuration, scheduling,
  user delivery and recursive delegation. File I/O is rooted in their workspace.
- A live test exposed a withheld draft being recorded as if it were delivered.
  The loop now records final answers only after worker collection and the steering
  check; a regression verifies that withheld drafts never enter context or memory.
- Parent cancellation propagates to the worker. Reports are delivered once,
  after the worker slot is released; interruption retains evidence and disallows
  automatic resume/replay. Workers cannot accidentally enter Telegram's normal
  delivery queue or the searchable conversation journal.
- Shell isolation is conditional on OS support, with no unrestricted fallback.
  A macOS test verifies allowed workspace writes, denied external reads/writes,
  symlink escape rejection and blocked access to a real local HTTP test server.
  The A15 lacks the required Landlock capability, so no worker shell is exposed.
- Hardened input copying against FIFO/symlink opens; removed the unused text-read
  wrapper. Truncated worker outputs no longer point to nonexistent memory entries.
- Existing Calendar ownership/family grants, read-only Google roles, idempotent
  creation and conditional updates remain covered by their regression tests.

## Validation

- Full `go test -race ./...` and `go vet ./...` passed on macOS. Additional
  end-to-end loop tests verified automatic worker reporting without leaking
  intermediate exchanges into the parent context or journal.
- Android/arm64, Linux/amd64, FreeBSD/amd64, OpenBSD/amd64 and NetBSD/amd64 builds
  passed. Linux shell enforcement still depends on the deployment kernel;
  cross-compilation alone does not verify it.
- Galaxy A15: checksum-verified 0.19.0 installation, idle preflight, successful
  restart and offline doctor. A local live smoke task completed with Astra low
  as parent, Sol 6 low as worker and Sol 6 high for hosted web research. The
  worker returned the official Termux URLs and the parent consumed its report.
  No Telegram message or Calendar mutation was part of the test.

The small shared loop remains intact. Budgets are bounded but are not hard
CPU/disk quotas, and the subscription adapter remains dependent on the provider's
backend protocol. See [worker limits](delegation.md) for the operational boundary.
