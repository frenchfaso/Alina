# Review: reliability and lean Go

Reviewed 0.19.1-poc at `ecfac1ccd64a65ee8773bd8469733668c9e3fc54`, including
the shared loop, memory/dream/checkpoint flow, model selection and OAuth,
workers, Calendar, Telegram delivery/steering/approvals, service lifecycle,
setup/configuration and CLI. All findings and cleanups below are addressed in
0.19.2-poc; descriptions retain the original reproduction evidence.

The core remains understandable: one agent loop, explicit tool sets, bounded
workers, a durable archive independent of working-context compaction, and one
global personality. Most complexity belongs to persistence and channel
delivery. No P0/P1 issue was confirmed in the reviewed paths; five P2 bugs
and one P3 interface gap were reproduced.

## Confirmed bugs

### P2 — One broken outgoing attachment blocks later Telegram replies

`telegram_outbox.go:107-114,216-218`, `telegram.go:523-526,566-569`.

If an outbox snapshot is missing or its size/hash changed, `sendDocument`
returns an ordinary error. Delivery aborts the old job and skips every newer
job for the same recipient. Subsequent attempts retry the same unrecoverable
attachment indefinitely. Other people can still receive replies, but the
affected person cannot receive newer answers.

Reproduced by using `queueFile` to create a real snapshot, removing that file,
then queuing a second completed text-only job. After three delivery attempts,
the older text had been sent once, both jobs remained pending, and the newer
reply had never been sent.

Minimal fix: distinguish permanent attachment validation failures from
transient transport errors. Record the failed part with its actual outcome,
send one short explanation, and continue the remaining parts/newer jobs.
Keep network/429/5xx retries and never record a missing file as sent. Cover
missing and hash-changed snapshots plus recovery from a transient upload error.

### P2 — Cancellation can wait behind another worker's OAuth renewal

`auth.go:93-110`, `continuity.go:81-92`.

`Auth.get` holds a plain mutex across the refresh HTTP request. Provider copies
share the same `*Auth`, while main and worker inference use separate gates.
A main request waiting for a worker's renewal cannot observe its own context
cancellation until that mutex is released. The default authentication HTTP
client permits a 180-second request timeout. `/stop` cancels the job context,
but that blocked job cannot finish promptly.

Reproduced through actual `jobModel.Complete` paths with synthetic credentials
and a controlled transport: worker renewal was held; a second person's main
inference waited; cancelling it left it blocked past the test's 150-ms deadline.
It returned only after the unrelated renewal was released.

Minimal fix: keep one refresher, protect short credential state changes with
the mutex, and let waiters select between renewal completion and `ctx.Done()`.
No additional dependency or general concurrency framework is needed. Preserve
the existing protection against concurrent refresh-token rotation.

### P2 — Background reasoning is omitted for non-default global models

`provider.go:303-304,318-319`, `reasoning_catalog.go:323-326`.

Changing the global ChatGPT model to an available model such as `gpt-6-sol`
can silently drop configured reasoning from dreams/checkpoints. Fixed global
jobs do not resolve catalog metadata through `refreshJobModel`; the Responses
adapter emits reasoning only for Sol 6.1/Astra, selected catalog metadata or
search calls. Accounting logs still report the configured effort.

Reproduced using `refreshJobModel`, `jobModel.Complete` and the real ChatGPT
adapter against a fake transport: a `gpt-6-sol` dream configured to xhigh sent
no `reasoning` object. The current Sol 6.1 device default is not affected.

Minimal fix: use the cached capabilities of the configured global model for
background calls without applying a person's model preferences. Keep model
defaults separate from supported parameters, and log the effort actually sent.
Test an explicit non-default model for both dream and checkpoint requests.

### P2 — Calendar PATCH does not clear incompatible date fields

`calendar_write.go:173`, `calendar.go`'s `calendarTime` JSON tags.

Changing an all-day event into a timed event omits `date` from the PATCH body
rather than explicitly clearing it. Google merges fields, leaving the old date
beside the new `dateTime`. The reverse conversion also retains incompatible
`dateTime`/`timeZone` fields. The existing mock replaces the whole nested object,
so its passing tests mask this failure.

Reproduced with the existing write fixture and a merge-aware transport. The
outgoing timed PATCH omitted the required date clearing and received HTTP 400.
The [Google client issue](https://github.com/googleapis/google-api-nodejs-client/issues/1559)
documents the need for explicit `null` when converting an all-day event.

Minimal fix: serialize PATCH-only start/end objects with incompatible fields
explicitly set to `null`; retain `If-Match`. Cover both conversions and a timed
timezone removal. Creation payloads can keep the existing compact representation.

### P2 — Failed worker starts leave copied input files without a job

`delegate.go:67-78,115-124`.

Before registering the job, a start creates its workspace and copies files.
If a later input has the same basename, or another pre-start step fails,
cleanup cancels contexts and releases the busy slot but leaves copied files
behind. There is no job record through which to inspect or track those copies.
Repeated failed attempts can each retain up to the 32-MiB input limit.

Reproduced by supplying the same input twice: the tool rejected the second
basename, no worker was registered, and the first copied file remained.

Minimal fix: one deferred pre-start rollback for context, busy slot and the
new workspace. This also removes the repeated error-path `cleanup()` calls. Retain
artifacts/traces for workers that actually started, including failed workers.

### P3 — Approval forms survive cancellation and expiry

`telegram.go:333-346,531-541`.

Forms disappear after their own callback, but their message IDs are not retained
for other lifecycle changes. `/stop`, expiry, steering, local API decisions or
restart leave stale buttons visible until clicked. Authorization still rejects
stale approvals; this is a user-interface issue, not a permission bypass.

Reproduced by sending a form for a persisted approval job, changing that job to
cancelled, then running delivery/progress: the final message was sent but no
form deletion occurred.

Minimal fix: retain the form message ID in the existing SQLite state store and
use the existing notification worker to clean it when that approval ends.

## Worthwhile simplifications

- **One configuration decoder.** `LoadConfig` permissively unmarshals the file;
  `checkedConfig` reads it again and strictly decodes it. A misspelled field is
  accepted at startup/setup but rejected by diagnostics. Share one strict
  decoder while preserving the raw `config apply` repair path. This removes a
  second file read and inconsistent interpretation.
- **One query embedding per shared recall.** `memory_access.go:16-21` calls
  `Memory.Recall` for family and mind; each embeds the same query separately.
  A focused test observed two HTTP calls for one household recall. Reuse the
  query vector when both stores use the same embedding space. This affects only
  optional semantic search; default text-only recall makes no embedding calls.
- **Fix the stale search setup hint.** `setup_advanced.go:79` says a blank
  research model follows the ChatGPT model. Actual default research is Sol 6 high.
- **Remove unused Telegram input fields.** `tgFile.UniqueID` and `tgFile.MIME`
  are decoded but never consumed. MIME is independently determined from file
  bytes. This is small cleanup, not a reason to alter the attachment format.

The most useful Go improvements are deferred rollback, cancellation-aware
waiting, typed permanent delivery errors and one configuration decoder. No
obvious unused production helper was found. Retained legacy tables/readers are
compatibility paths for existing archives, not disposable dead code. Keep the
small internal package and shared loop; a plugin framework, generic repository
layer or mechanical split into more packages would not resolve these findings.

System/tool/dream/checkpoint prompts remain reasonably compact and serve
different purposes. No blanket rewrite is warranted. Improve capability
handling in code rather than adding model-specific prompt instructions.

## Implemented in 0.19.2

- Permanent attachment validation failures produce a durable `failed` part,
  one brief notice and continued delivery. Transient uploads/notices still retry.
- OAuth has one active renewal and independently cancellable waiters. Successful
  rotation is saved before waiters resume; failed/cancelled renewal remains retryable.
- Fixed global jobs resolve cached model metadata independently of personal
  preferences. Dream and checkpoint efforts reach the wire or fall back to
  supported defaults; logs no longer claim an effort omitted by the adapter.
- Calendar PATCH explicitly clears incompatible nested date/time fields. Tests
  now merge nested objects rather than replacing them.
- One deferred rollback releases failed worker starts and removes only their
  newly created, rooted workspace; started workers retain artifacts and traces.
- Approval IDs/message IDs use existing SQLite state and the notification worker
  for cleanup through all lifecycle exits, without another timer or goroutine.
  A saved form is reused if its outer delivery receipt was not recorded, so its
  original message ID is not replaced by an avoidable duplicate.
  Forms predating the release still require a callback because their IDs were
  never saved. Telegram may also refuse deletion of old messages.
- Startup/setup/diagnostics share one strict config decoder. Raw merge-patch
  repair still accepts unrelated invalid types without resetting bot identity.
- Shared recall embeds each query once per endpoint/model, including failure
  fallback, and correctly combines semantic availability across the two stores.
- The advanced setup research hint matches Sol 6 high; unused Telegram input
  fields and the duplicate config-reader/helper were removed.

Permanent regression tests cover these behaviors with synthetic fixtures. See
[release verification](verification.md) for final checks and A15 deployment.
The shared loop and prompt structure remain unchanged; no dependency was added.
